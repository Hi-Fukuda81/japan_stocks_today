# 文体・読み上げのガイド

## 全体
- 語り口は「です・ます」調。落ち着いたニュース読み上げのトーン。キャラクターの口癖(「〜なのだ」など)は付けない。
- 台本全体で 1000〜2200 字(VOICEVOX 話速 1.15 で約3〜5分)。最低 600 字。
- `lines` の1要素 = 1セリフ = 1文。**45 字以内**(目安 40 字)。1要素に2文を入れない。
- 1セリフは字幕として画面に出る。読みやすさを優先し、長い文は2つに分ける。
- 毎回同じ言い回しにしない。つなぎの言葉、シーンの入り方、解説の切り口を日によって変える。

## 数値
- 数値は **半角数字**。全角数字は使わない。
- 単位(件、%、ポイント、円、銭)が付いた数値はすべて data.json と照合される。data.json にない数字(自分で計算した差・合計・割合など)は書かない。
- 照合できる単位は 件・%・ポイント・円・銭 だけ。「億円」「社」「倍」「bp」などの単位や漢数字の数値は NG になる。
- 件数は `filings` の値を「412件」のように言う。「約400件」のように丸めない。
- ドル円は「159円35銭」。前日比は「1銭の円安」のように `change` と `direction` を使う。
- 水準に上昇・低下を続けるときは「2.87%に上昇」「159円35銭まで円安」のように「に」「まで」を入れる(入れないと前日比として照合される)。
- 年限と数値の組み合わせ(どの年限の利回りか)は自動では照合されない。data.json をよく見て書く。
- 国債金利は `yield_pct` を「2.87%」のように言う。前日比は `change_pt` を「0.046ポイント低下」「0.012ポイント上昇」と言う。符号は言葉で表し、「マイナス0.046」とは言わない。
- 制度の基準値は `reference` にあるものだけ使える(`large_holding_threshold_pct` = 大量保有報告書の提出義務が生じる保有割合、`change_report_threshold_pct` = 変更報告書が必要になる保有割合の増減)。
- 日付は「11月13日」の形式。data.json にある日付だけを使う。曜日は書かない。
- ドル円と国債金利は、動画の日付より前の日のデータのことがある(`usdjpy.date`、`jgb.date`、`notes`)。そのときは「11月12日時点で」と日付を言い、「きょうの」とは言わない。

## 用語・読み
- 社名は data.json の表記のまま使う(「株式会社」は外してある)。証券コードは読み上げない。
- 提出者(ファンドや金融機関)の名前が長いときは、そのまま1セリフに収まる範囲で言う。収まらなければそのセリフでは社名だけを言い、説明を次のセリフに分ける。
- 用語は次の表記に統一する: EDINET、大量保有報告書、変更報告書、臨時報告書、公開買付、自己株券買付状況報告書、ドル円、長期金利(10年の国債金利のこと)。

## シーンごとの内容
| シーン | 内容 |
|---|---|
| 01_opening | 動画の日付と「夕方便」であること。きょうの開示の全体像を一言で(提出書類の総数など)。2〜3セリフ |
| 02_overview | `filings.total` と `filings.by_type` の上位。どの種類の書類が多かったか。解説を1つ。4〜6セリフ |
| 03_holdings | `large_holdings` の件数(`count` は全体。`listed_count` / `listed_new_count` / `listed_change_count` は発行会社が上場会社のものだけなので、「上場会社については」と断って言う)と、`items` から発行会社と提出者を数件。解説を1〜2セリフ。6〜10セリフ |
| 04_events | `tender_offers` と `extraordinary` の件数と `items`(会社名と提出事由)。`buybacks.count`。該当がなければ「ありませんでした」と言う。解説を1つ。4〜8セリフ |
| 05_usdjpy | ドル円の水準、前日比(円安/円高)、過去30日の高値・安値との位置関係。3〜5セリフ |
| 06_jgb | 10年を中心に年限別の金利と前日比。3〜6セリフ |
| 07_ending | まとめ1〜2セリフ、締めのあいさつ。免責文は読み上げない |

## 解説(読み上げるだけにしないために)
各シーンで、その書類や数字が「何を意味するか」「なぜ見られているか」を一般的な制度の説明として入れる。例:
- 大量保有報告書: 上場会社の株式を一定の割合を超えて持った投資家が提出する書類で、誰が大株主になったかがわかる。
- 変更報告書: すでに大量保有報告書を出している投資家の保有割合が一定以上増減したときに出る。
- 臨時報告書: 代表取締役の異動や主要株主の異動など、重要な出来事が起きたときに会社が出す。
- 公開買付届出書: 市場の外で株式を買い集める手続き(公開買付)を始めるときに買付者が出す。
- 長期金利: 10年の国債金利。住宅ローンの固定金利や企業の資金調達コストの目安になる。

制度の一般的な説明は書いてよい。個別の提出について、data.json にない事情(保有割合、買付価格、目的、株価への影響)は書かない。
推測を述べるときは「〜とみられます」「〜の可能性があります」と推測であることがわかる言い方にする。

## タイトル・要約
- `title`: 「きょうの日本株【夕】11/13 大量保有報告書 35件｜公開買付・臨時報告書まとめ」のように、
  必ず「きょうの日本株【夕】月/日」で始め、いちばん目立つ数値を単位付きで入れる。100字以内。
- `description_summary`: 概要欄の冒頭に入る2〜3文の要約。事実のみ。
